## 1. Диагноз: чем текущая система ограничена

Система хорошо построена как **библиотека знаний**. Её предел в том, что она **статична**:
знания втекают только вручную, через вас.

| # | Проблема | Доказательство | Следствие |
|---|---|---|---|
| **D1** | **Нет обратной связи.** Правила меняются только когда вы сами заметили дрейф | git-история: серия коммитов `fix drift`, `fix(benchmark run-2)`, `fix(benchmark run-3)` | Каждый урок сессии теряется. Одни и те же поправки вносятся заново |
| **D2** | **Codex получает плоский снимок.** `sync-rules.bat` склеивает `AGENTS.md` + `codex/AGENTS.md` в один always-on файл ~15 КБ. Скиллы ему не раздаются вообще | `sync-rules.bat` копирует только в `%CLAUDE_HOME%\skills`. `~/.agents/skills` — ручное зеркало от 24 августа, скрипт его не трогает | Весь слой скиллов де-факто Claude-only. При переходе на Codex вы теряете 14 скиллов |
| **D3** | **Роутинг — рекомендация, а не механизм.** `rules-index.md` говорит «читай 1-3 файла», но ничто это не проверяет | нет ни одного хука/скрипта на чтение правил | Token economy держится на дисциплине модели, то есть не держится |
| **D4** | **Качество дизайна не верифицируется.** `anti-slop-audit.md` — документ, который агент может прочитать, а может нет | `rules-index.md` сам помечает его как «читать при триггере» | Anti-slop срабатывает, когда вы вспомнили про него |
| **D5** | **Decision Lineage ведётся на честном слове** | `templates/project-state.md` — правила ledger есть, принуждения нет | Ledger заполняется неравномерно, resumption деградирует |
| **D6** | **Нет контроля дублей скиллов** | `AGENTS.md` запрещает дубли, но детектора нет. Сейчас пересекаются `craft-audit` / `make-interfaces-feel-better` / `motion-rules` / `emil-design-eng` — четыре источника про одно | Растёт шанс, что сматчится не тот скилл |
| **D7** | **Calibration и anti-sycophancy не измеряются** | `УВЕРЕННОСТЬ: X%` — правило без обратной связи | Неизвестно, калиброваны ли проценты. 90% может на деле быть 60% |
| **D8** | **Задекларированное ≠ включённое** | `RULES-GOVERNANCE.md` #L2 пишет, что guard-hook подключён глобально в `~/.claude/settings.json`. В файле **нет ключа `hooks`** | Защита от `rm -rf /`, force-push и `--no-verify` сейчас не работает нигде |

Пункт **D1** — корневой. Остальные — его проявления: система не умеет замечать
собственные проблемы, поэтому каждую из них ловите вы.

## 2. Что взять из ECC (ранжировано по отдаче для вас)

ECC заточен под полиглот-разработку: 40 из 71 агента — ревьюеры и build-resolver'ы под
языки, которые вам не нужны. Ценность не в каталоге, а в **механизмах**. Отбор под
продуктово-дизайнерский пайплайн:

### Тир 1 — замыкают цикл (ядро апгрейда)

| Механизм ECC | Что даёт вам | Адаптация |
|---|---|---|
| `continuous-learning-v2` — инстинкты | Сессии перестают быть одноразовыми | Node вместо bash+python; без демона; домены под ваш пайплайн, не под код |
| `rules-distill` — принципы из скиллов в правила | **Главный множитель:** инстинкт → правило в `memory-bank/` → раздача обоим агентам | У ECC инстинкты живут в data-каталоге вечно. У вас есть куда их промотировать — ваш же репозиторий правил |

## 3. Целевая архитектура v3

### 3.1 Смена ролей (Codex-first)

```
БЫЛО                                  СТАЛО
Claude  = оркестратор пайплайна       Codex  = оркестратор + исполнитель
Codex   = исполнитель кода по плану   Claude = специалист: Figma MCP, визуальные решения
```

Конкретно:
- `codex/AGENTS.md` становится основным tool-файлом, `claude/CLAUDE.md` — дополнением.
- Таблица «Что делает Claude vs Codex» в `AGENTS.md` переворачивается.
- **Скиллы начинают раздаваться Codex'у**: `sync-rules.bat` синкает `skills/` →
  `~/.codex/skills/` (сейчас не синкает никуда, кроме Claude). Для каждого скилла
  генерируется `agents/openai.yaml` — конвенция интерфейсных метаданных Codex
  (у `make-interfaces-feel-better` и `serega-*` он уже есть, у ваших 11 — нет).
- Claude вызывается явно, когда нужен Figma MCP или визуальное решение.

### 3.2 Цикл обучения (ядро)

```
сессия Codex/Claude
      │
      │ PostToolUse + UserPromptSubmit hook (node, детерминированно)
      ▼
observations.jsonl  (per-project, хеш от git remote)
      │
      │ /distill — скилл, запускается вами (НЕ демон)
      ▼
инстинкты  .yaml: trigger, action, confidence 0.3–0.9, domain, scope, evidence
      │
      ├─ SessionStart hook инжектит топ-N с confidence ≥ 0.7
      │
      │ confidence ≥ 0.9 И встречен в 2+ проектах
      ▼
/promote → патч в memory-bank/  ← вы ревьюите и коммитите
      │
      ▼
sync-rules.bat → ~/.codex/ + ~/.claude/   (раздача обоим агентам)
```

Отличие от ECC в последнем шаге. У них инстинкты — конечная станция. У вас есть
репозиторий правил, то есть инстинкт может стать **правилом системы**. Это и делает
репозиторий самообучающимся, а не просто «агент с памятью».

**Домены инстинктов — под ваш пайплайн**, а не под код ECC:
`research` · `ia` · `design-system` · `craft` · `figma` · `frontend` · `pipeline` · `communication`

### 3.3 Детерминированное принуждение (хуки вместо надежды)

| Хук | Событие | Что делает | Чинит |
|---|---|---|---|
| `guard-hook.mjs` | PreToolUse | блок всегда-запрещённых команд — **уже написан, надо включить** | D8 |
| `observe.mjs` | PostToolUse, UserPromptSubmit | пишет observations | D1 |
| `inject-instincts.mjs` | SessionStart | подмешивает топ-N инстинктов | D1 |
| `anti-slop-check.mjs` | PostToolUse на `.tsx/.css/...` | сигналы из вашего `anti-slop-audit.md` | D4 |
| `routing-hint.mjs` | UserPromptSubmit | определяет тип задачи, подсказывает строку `rules-index.md` | D3 |
| `delivery-gate.mjs` | Stop | не даёт закрыть сессию, если artifacts менялись, а Lineage нет | D5 |

Всё на Node (boring tech, и python тут сломан). Для Codex — `~/.codex/hooks.json` с
доверием через `/hooks`. Для Claude — `~/.claude/settings.json`.

### 3.4 Новая структура репозитория

```
ai-rules/
├── AGENTS.md                  ← ядро, роли перевёрнуты
├── rules-index.md             ← + домены инстинктов

├── skills/                    ← раздаются ОБОИМ рантаймам
│   ├── <14 существующих>      ← + agents/openai.yaml каждому
│   ├── emil/<N>               ← скиллы Эмиля (решение по объёму — за вами)
│   ├── distill/               ← НОВОЕ: observations → инстинкты
```

## 5. Риски и ограничения

1. **Хуки Ф3 могут мешать.** Stop-хук, блокирующий завершение, — самый агрессивный
   механизм в наборе. Предлагаю его только после обкатки Ф2 и сразу с рубильником
   (env-переменная отключения).
2. **Инстинкты могут выучить неверное.** Если в сессии вы согласились на плохое решение,
   система это закрепит. Защита: промоушен в правила **только через ваш ревью**, никогда
   автоматически.
3. **Приватность наблюдений.** В `observations.jsonl` попадают ваши промпты. Каталог вне
   репозитория, в `.gitignore` на всякий случай, экспортируются только инстинкты (как у ECC).
4. **Объём изменений.** Это переписывание трёх верхних слоёв системы. Откат — через git,
   но привычный порядок работы изменится.
5. **Доверие хукам в Codex.** Каждый хук надо один раз подтвердить через `/hooks`; при
   изменении файла доверие сбрасывается по хешу — то есть после каждого `sync-rules.bat`,
   меняющего хуки, потребуется переподтверждение.
