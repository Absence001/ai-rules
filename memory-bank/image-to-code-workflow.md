# Image To Code Workflow

## Когда использовать

Когда есть скриншот/референс и нужно восстановить web/mobile prototype в коде.

## Не делать

- Не начинать код сразу.
- Не использовать Figma MCP, если пользователь попросил без MCP.
- Не создавать свою DS с нуля, если задача быстрый prototype.
- Не копировать бренд/логотипы как готовые активы, если их нет; использовать placeholders.

## Порядок

1. Определить тип скрина: web landing, app screen, dashboard, mobile, marketing, editorial.
2. Выбрать visual register.
3. Разложить на секции.
4. Извлечь visual inventory:
   - typography;
   - colors;
   - spacing;
   - radius;
   - shadows;
   - imagery;
   - layout grid;
   - components.
5. Составить component tree.
6. Выбрать стек и проверить зависимости.
7. Спросить подтверждение на реализацию.
8. Реализовать.
9. Сделать visual diff checklist:
   - структура;
   - пропорции;
   - типографика;
   - цвета;
   - spacing;
   - responsive;
   - states.
10. Провести anti-slop audit.

## Для длинных страниц

Анализировать секциями. Не пытаться держать весь сайт одним большим скрином.
