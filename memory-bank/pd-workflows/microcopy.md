# Microcopy

Content design: тексты в интерфейсе. Метки, error messages, empty states, button labels, microcopy.

## Главный принцип

> *«labels are words»* — Pavel Samsonov

Microcopy — это код продукта. Метка кнопки = функция в системе. Каждое слово несёт смысл.

## Voice & Tone

**Voice = постоянная.** Кто наш продукт как личность? Дружелюбный / профессиональный / прямой / playful?

**Tone = зависит от контекста.** Один продукт может иметь разные tones в разных ситуациях:
- Onboarding → warm, welcoming
- Error → calm, helpful, не паникёрский
- Success → краткий, не overwhelming
- Critical action → серьёзный, ясный

**Test:** прочитай вслух. Если звучит **не так как ваш продукт говорит** — переписывай.

## Hard rules

| Правило | Значение |
|---|---|
| **Метки на языке пользователя**, не жаргон команды | Avoid `crm-pipeline-stage-3` |
| **Sentence case** > Title Case (для большинства UI) | Чище, легче читать |
| **Verb-first для CTA** | «Сохранить заказ» > «Заказ» |
| **Краткость** — каждое слово оправдано | Удалить если можно |
| **Конкретика** > generic | «Сохранить и продолжить» > «Submit» |
| **Active voice** > passive | «Загружаю файлы» > «Файлы загружаются» |
| **Реалистичный контент** | Не Lorem / John Doe / Acme |

## CTA / Button labels

| ❌ Плохо | ✅ Хорошо |
|---|---|
| `Submit` | `Сохранить заказ` |
| `OK` | `Понятно` / `Закрыть` (зависит от контекста) |
| `Click here` | `Открыть заказ` |
| `Yes` / `No` | `Удалить` / `Отмена` |
| `Continue` | `Перейти к оплате` |
| `Send` | `Отправить сообщение` |

**Формула:** глагол + объект. Конкретно что произойдёт.

## Error messages

**Структура:** что случилось + что делать.

| ❌ Плохо | ✅ Хорошо |
|---|---|
| `Error 500` | `Не удалось загрузить заказы. Попробовать снова?` |
| `Что-то пошло не так` | `Соединение прервано. Проверьте интернет и попробуйте снова.` |
| `Invalid input` | `Email должен содержать @. Пример: user@domain.com` |
| `Failed` | `Не удалось сохранить. Изменения остались — попробуйте ещё раз.` |

**Принципы:**
- Не вините пользователя (`You entered wrong data` → `Email format не распознан`)
- Дайте actionable next step
- Используй plain language, не error codes
- Не «sorry» в каждом сообщении (становится шумом)

## Empty states

**Первое впечатление!** Empty state часто = onboarding.

**Структура:**
1. Что будет здесь (когда контент появится)
2. Почему сейчас пусто (если не очевидно)
3. CTA: как добавить контент

| ❌ Плохо | ✅ Хорошо |
|---|---|
| `No data` | `Здесь будут ваши заказы. Создать первый?` |
| `Empty` | `Пока нет проектов. Импортировать из Figma или начать с нуля.` |
| `Nothing here` | `Поиск ничего не нашёл по запросу «<query>». Попробовать другие слова?` |

## Loading states

Кратко, конкретно:

| ❌ Плохо | ✅ Хорошо |
|---|---|
| `Loading...` | `Загружаю заказы…` |
| `Please wait` | `Обрабатываю платёж…` |
| `Processing` | `Сохраняю изменения…` |

Если > 5 секунд — добавь прогресс или объяснение что занимает время.

## Success messages

Не overdo. Краткий confirm + next step (если уместно):

| ❌ Слишком | ✅ Хорошо |
|---|---|
| `Congratulations! Your order has been successfully placed!` | `Заказ #1234 оформлен. Открыть?` |
| `Great job! Your profile has been saved!` | `Профиль сохранён.` |

## Labels на формах

| Правило | Деталь |
|---|---|
| **`<label>` для каждого поля** | НЕ placeholder вместо label |
| **Sentence case** | `Имя пользователя` не `Имя Пользователя` |
| **Без двоеточия в конце** | Современный стандарт (зависит от контекста) |
| **Help text если нужно** | Под полем, мелким шрифтом |
| **Required marker** | `*` или текст «Обязательно» |

## Confirmation dialogs

Для деструктивных действий:

```
Title: Удалить заказ?
Body: Это действие нельзя отменить. Все данные заказа #1234 будут удалены.
Cancel: Отмена
Confirm: Удалить
```

**Confirm button = действие**, не «Yes». Делает destructive intent явным.

## Microcopy в навигации

| Правило | Деталь |
|---|---|
| **2-3 слова max** для tab labels | Длинные = обрезаются |
| **Существительные** для разделов | `Заказы` не `Просмотр заказов` |
| **Иконка + текст** > только иконка | Кроме явных стандартов (home, search) |

## Inclusive language

- **Gender-neutral** где возможно (`пользователь` > `он/она`)
- **Plain language** (не sophisticated синонимы ради них)
- **Без культурно-специфичных метафор** (если продукт global)
- **Без assumed knowledge** (объясни термины которые могут быть незнакомы)

## Test чек-лист

- [ ] Прочитал вслух — звучит как наш продукт говорит?
- [ ] Каждое слово оправдано (можно удалить?)
- [ ] CTA — глагол + объект?
- [ ] Error содержит что случилось + что делать?
- [ ] Empty state объясняет что будет + как добавить?
- [ ] Без жаргона / internal naming?
- [ ] Active voice > passive?
- [ ] Realistic content (не Lorem)?

## Anti-patterns

| Anti-pattern | Симптом |
|---|---|
| Generic CTA (`Submit`, `Click here`) | Не понятно что произойдёт |
| Error без actionable next step | Frustrating |
| Empty state как «No data» | First impression сломан |
| Жаргон команды в UI | Confusing |
| Title Case везде | Устарело, тяжело читать |
| Lorem Ipsum | Не finished |
| Sophisticated синонимы ради сложности | Утомляет |
| Passive voice без причины | Дистанцирует |
| Apologetic tone в каждом сообщении | Раздражает |
