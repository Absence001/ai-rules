# Distill — наблюдения в инстинкты

Превращает сырые наблюдения сессий в **инстинкты**: атомарные правила «триггер → действие»
с уверенностью. Это ручной шаг цикла обучения — фонового агента нет намеренно
(он не выживает на нативной Windows, см. `memory-bank/meta/learning-loop.md`).

**Запускается только по явной просьбе пользователя.** Инстинкты меняют поведение
во всех будущих сессиях, поэтому дистилляция никогда не идёт сама собой.

## Что такое инстинкт

Атомарное правило: **один триггер, одно действие**.

```
trigger:  когда нужен новый компонент
action:   сначала проверить DS на похожий и предложить переиспользование
domain:   design-system
confidence: 0.7
```

Не инстинкт: «делать хорошо», «учитывать контекст», «быть внимательнее к деталям».
Это не атомарно и не проверяемо. Если из наблюдения не выводится конкретное
«когда X → делай Y» — инстинкта нет, не выдумывай его.

## Шкала уверенности

| Значение | Смысл | Поведение |
|---|---|---|
| 0.3 | Предположение | Предлагается, не навязывается |
| 0.5 | Умеренная | Применяется, когда релевантно |
| **0.7** | Сильная | **Порог инжекта в сессию** |
| 0.9 | Почти точно | Порог промоушена в правила |

Новый инстинкт начинается с 0.3. Подтверждение даёт +0.1, опровержение −0.3.
Молчание дольше 60 дней — −0.1 (затухание). Асимметрия намеренная: ошибиться,
навязав неверное правило, дороже, чем не выучить верное.

## Домены

`research` · `ia` · `design-system` · `craft` · `figma` · `frontend` · `pipeline` · `communication`

Домены — под продуктово-дизайнерский пайплайн. Если паттерн никуда не ложится,
скорее всего это не инстинкт, а разовый случай.

## Scope: проект или global

| Тип паттерна | Scope | Пример |
|---|---|---|
| Конвенции стека и проекта | **project** | «в этом проекте токены через CSS-переменные, не Tailwind-конфиг» |
| Структура файлов | **project** | «компоненты лежат в src/ui, не src/components» |
| Решения по домену продукта | **project** | «для этой аудитории не использовать термин „дашборд“» |
| Методология работы | **global** | «не начинать IA без research.md» |
| Коммуникация | **global** | «не показывать варианты без рекомендации» |
| Безопасность и необратимое | **global** | «перед удалением — посмотреть, что удаляем» |

По умолчанию **project**. Global — только когда правило очевидно не зависит от проекта.

## Workflow

### 1. Прочитать наблюдения

```bash
node scripts/instincts.mjs observations 200
```

Наблюдения двух видов: `💬` промпты пользователя и `🔧` вызовы инструментов
(имя, цель, провал). Содержимого файлов там нет — только цели.

### 2. Искать три сигнала

**Коррекция пользователя** — самый ценный сигнал. Пользователь поправил, агент
согласился по существу. Ищи в промптах: «не надо», «не так», «у нас уже есть»,
«я же говорил», «переделай», «опять».

> `💬 не надо плодить компонент, у нас уже есть Card`
> → trigger: нужен новый компонент / action: сначала проверить DS на похожий

**Разрешение ошибки** — что-то упало (`🔧 ... ✗`), потом заработало. Что изменилось?

> `🔧 Bash ✗ npm run build` → `🔧 Edit tsconfig.json` → `🔧 Bash npm run build`
> → trigger: build падает на путях / action: проверить paths в tsconfig до правки импортов

**Повторяющийся workflow** — одна и та же последовательность 3+ раз.

> Read `<artifact>.md` → `Edit tokens.css` → `Bash npm run build` (×4)
> → trigger: правка токенов / action: после правки прогнать сборку, не откладывая

### 3. Проверить на дубль перед записью

```bash
node scripts/instincts.mjs status
```

Та же первопричина при другом симптоме — **подтверди существующий**, не плоди новый:

```bash
node scripts/instincts.mjs reinforce <id>
```

Это принцип Боле из `growth-log` ECC: одна первопричина — одна запись.
Дубли размывают уверенность между двумя записями, и ни одна не дорастает до порога.

### 4. Записать новые

```bash
node scripts/instincts.mjs add \
  --id reuse-before-create \
  --trigger "когда нужен новый компонент" \
  --action "сначала проверить DS на похожий и предложить переиспользование" \
  --domain design-system \
  --scope project
```

`--id` в kebab-case, описывает **паттерн**, не случай: `reuse-before-create`,
не `card-duplicate-incident`.

### 5. Показать пользователю и дождаться реакции

Выведи таблицей: что предлагается записать, на каком наблюдении основано, какой scope.
Неподтверждённое не записывай. Если пользователь спорит — работает
`memory-bank/meta/anti-sycophancy.md`: уступай при score ≥ 4, не раньше.

## Промоушен в правила

Когда инстинкт дорос до 0.9 и встретился в 2+ проектах:

```bash
node scripts/instincts.mjs promote        # кандидаты project → global
```

Дальше — **решение пользователя**, автоматизма здесь нет. Если правило того стоит,
оно переносится в `memory-bank/<категория>/<файл>.md` как обычное правило и
уезжает в git. С этого момента оно раздаётся обоим рантаймам через `sync-rules.bat`
и перестаёт быть инстинктом.

Критерий переноса: правило **объяснимо без ссылки на историю наблюдений**.
Если его можно обосновать только «мы так несколько раз делали» — оно ещё не правило.

## Гигиена

```bash
node scripts/instincts.mjs prune     # удалить выдохшиеся (уверенность упала до 0)
node scripts/instincts.mjs projects  # сколько инстинктов в каждом проекте
```

## Чего не делать

| ❌ | ✅ |
|---|---|
| Выдумывать инстинкт, когда сигнала нет | Нет сигнала — нет инстинкта, так и сказать |
| Записывать без показа пользователю | Сначала показать, потом записать |
| Делать неатомарные правила «работать аккуратно» | Один триггер, одно действие |
| Ставить 0.9 сразу «потому что очевидно» | Начинать с 0.3, растить подтверждениями |
| Плодить дубль при той же первопричине | `reinforce` существующий |
| Автоматически переносить в memory-bank | Перенос — только решением пользователя |
