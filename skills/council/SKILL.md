# Council — четыре голоса до решения

Модель — `council` из everything-claude-code (MIT). Переработан: вердикт проверяется
через Four Big Risks (Cagan), решение пишется в Decision Lineage, а не в заметки.

Связь с `memory-bank/meta/anti-sycophancy.md`: anti-sycophancy решает, **уступать ли**
на pushback. Council решает, **что выбрать**, когда спорить пока не с кем — кроме
собственной первой идеи.

## Когда да, когда нет

| Да | Нет — вместо этого |
|---|---|
| Два-три разумных пути, нет очевидного победителя | Фактический вопрос → просто ответить |
| Go / no-go: выпускать или доработать | Ревью кода → `code-diagnostics`, ревью движения → `review-animations` |
| Риск закрепиться на первой идее | Очевидная задача → просто сделать |
| Пользователь просит второе мнение | Решение уже в Decision Lineage → сослаться на запись (anti-sycophancy, score 1) |

## Голоса

| Голос | Линза |
|---|---|
| **Ведущий** (ты) | Долгосрочные последствия, целостность, сопровождаемость |
| **Скептик** | Оспаривает саму постановку: тот ли вопрос мы решаем? Предлагает самую простую альтернативу |
| **Прагматик** | Скорость, реальный пользователь, что можно выпустить сейчас |
| **Критик** | Края, худшие сценарии, почему план провалится |

## Workflow

### 1. Свести к одному вопросу

Что решаем? Какие ограничения? Что считаем успехом? Если вопрос размыт — **один**
уточняющий вопрос пользователю до совета.

### 2. Собрать минимум контекста

Только то, что меняет ответ: выдержки из `brief.md`, `srgid.md`, `ia.md`, метрики.
Не весь проект.

### 3. Сначала — своя позиция

До чтения других голосов запиши: позицию, три самых сильных довода, главный риск своего
варианта. Иначе синтез просто отзеркалит остальных.

### 4. Три голоса — независимо

**Защита от якоря — это и есть смысл совета.** Каждый голос получает только вопрос,
минимальный контекст и свою роль. **Не** всю переписку и **не** чужие ответы.

- **Есть подагенты** (Codex multi-agent, Claude Agent) — запусти три параллельно, каждому чистый контекст.
- **Подагентов нет** — пиши голоса по очереди, каждый строго от его роли, не перечитывая
  предыдущие. Это слабее: якорь частично остаётся. **Скажи об этом в вердикте** одной строкой.

Шаблон для голоса:

```
Ты — [РОЛЬ] в совете из четырёх голосов.
Вопрос: [вопрос]
Контекст: [только нужное]
Ответь:
1. Позиция — 1–2 предложения
2. Доводы — 3 коротких пункта
3. Риск — главный риск твоей рекомендации
4. Что упустят другие — одна вещь
Прямо, без оговорок, до 300 слов.
```

### 5. Синтез — с ограничителями

Ты и участник, и судья, поэтому:
- не отбрасывай чужой голос без объяснения;
- если голос изменил твою позицию — скажи прямо;
- самое сильное несогласие — **всегда** в вердикте, даже если отвергаешь его;
- если два голоса против твоей исходной позиции — это сигнал, а не шум.

### 6. Вердикт

```markdown
## Совет: [короткое название решения]

**Ведущий:** [позиция] — [почему, одна строка]
**Скептик:** [позиция] — [почему]
**Прагматик:** [позиция] — [почему]
**Критик:** [позиция] — [почему]

### Вердикт
- **Согласие:** [в чём сошлись]
- **Сильнейшее несогласие:** [главный спор]
- **Проверка постановки:** [оспорил ли Скептик сам вопрос]
- **Four Big Risks:** ценность ✓/✗ · удобство ✓/✗ · реализуемость ✓/✗ · жизнеспособность для бизнеса ✓/✗
- **Рекомендация:** [путь] · УВЕРЕННОСТЬ: X%
```

Four Big Risks — из `skills/ia-design` (Cagan). Риск с ✗ в рекомендованном пути назвать
словами и сказать, как его снять.

## Куда записать

Только если совет **изменил** решение — запись в Decision Lineage `artifacts/project-state.md`
с provenance «council». Не в отдельные заметки и не в чат «на память».
Совет, который подтвердил очевидное, не записывается.

## Anti-patterns

| ❌ | ✅ |
|---|---|
| Дать голосам всю переписку | Только вопрос и минимальный контекст |
| Спрятать несогласие в вердикте | Сильнейшее несогласие — отдельной строкой |
| Совет на очевидную задачу | Просто сделать |
| Выдать последовательные голоса за независимые | Сказать, что якорь частично остался |
| Записывать каждый совет | Только если изменил решение |
