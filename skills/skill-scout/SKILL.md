# Skill Scout — искать, прежде чем создавать

`AGENTS.md` запрещает создавать дубль функции, которая уже покрыта. Этот скилл делает
запрет исполнимым: прежде чем создавать, — найти.

Модель — `skill-scout` из everything-claude-code (MIT), переработан под эту систему:
Codex-локации, вендоринг через `skills/VENDOR.md`, правила маршрутизации R7.

Если пользователь прямо сказал «создавай с нуля, не ищи» — подтверди и создавай.

## 1. Зафиксировать намерение

- Что скилл делает (одно предложение)
- Когда срабатывает (триггеры)
- Домен: research / IA / DS / craft / движение / frontend / pipeline / другое
- 3–5 ключевых слов **на русском и английском** — описания скиллов в системе на обоих языках,
  поиск только на одном пропустит половину

## 2. Искать — от ближнего к дальнему

| # | Где | Как |
|---|---|---|
| 1 | Каталог и маршрутизация | `skills/README.md` — 30 скиллов с разведением; `rules-index.md` |
| 2 | Описания скиллов в репозитории | `grep -rilE "слово\|word" skills/*/SKILL.md` |
| 3 | **Может, это правило, а не скилл** | `grep -rilE "слово\|word" memory-bank/` — знание, которое нужно всегда, место в memory-bank |
| 4 | Установлено, но не в репозитории | `~/.codex/skills/`, `~/.agents/skills/`, `~/.claude/skills/` — сравни со списком `skills/` |
| 5 | Плагины | Codex: `[plugins.*]` в `~/.codex/config.toml`; Claude: `enabledPlugins` в `~/.claude/settings.json` |
| 6 | Известные внешние наборы | `emilkowalski/skills` (уже завендорен), `affaan-m/everything-claude-code` (311 скиллов) |
| 7 | GitHub | `gh search repos "<word> skill SKILL.md" --sort stars --limit 10` |

Шаги 1–3 обязательны. Дальше — пока не нашлось покрытие.

## 3. Решить

| Нашлось | Решение |
|---|---|
| Скилл в репо закрывает задачу | **Переиспользовать.** Ничего не создавать; если не срабатывает — проблема в описании, правь его |
| Скилл в репо закрывает частично | **Расширить** его, а не плодить второй |
| Это знание, нужное всегда | **Правило в memory-bank**, а не скилл |
| Установлен локально, но не в репо | **Внести в репо** — иначе он вне source of truth |
| Есть внешний качественный | **Завендорить** по `skills/VENDOR.md`: провенанс, коммит, лицензия; `SKILL.md` не править |
| Ничего нет | **Создать** — шаг 4 |

Внешний источник проверять до вендоринга: лицензия, дата последнего коммита,
что скилл делает на самом деле (прочитать `SKILL.md` целиком, а не описание),
нет ли в нём команд и скриптов, которые что-то запускают без спроса.

## 4. Если создаём

- [ ] Имя в kebab-case (R5)
- [ ] `description`: что делает + когда + **явное «НЕ для X»** — без границы скилл перехватывает чужие запросы
- [ ] `agents/openai.yaml` — без него Codex не покажет скилл в интерфейсе
- [ ] Строка в каталоге `skills/README.md` (R7a)
- [ ] Если касается движения или полировки — строка в таблице «Разведение» (R7b)
- [ ] `node scripts/rules-lint.mjs` → чисто, затем `sync-rules.bat`

## Формат ответа

| Кандидат | Где | Покрытие | Решение |
|---|---|---|---|
| `craft-audit` | репо | 70% — нет X | расширить |

Ниже — одна строка рекомендации с обоснованием. Без меню из пяти вариантов.

## Anti-patterns

| ❌ | ✅ |
|---|---|
| Искать только по-английски | Ключевые слова на обоих языках |
| Создать скилл под знание, нужное всегда | Это правило в memory-bank |
| Поставить внешний скилл в `~/.codex/skills` руками | Завендорить в репо, иначе он вне source of truth |
| Довериться описанию внешнего скилла | Прочитать `SKILL.md` целиком до вендоринга |
| Создать без «НЕ для X» | Граница в описании обязательна |
