# RULES-GOVERNANCE — управление системой правил ai-rules

> Материальный паспорт для **самого репозитория правил** (не для проектов). Здесь фиксируется,
> как поддерживается целостность ai-rules, чем и как это проверяется, и append-only журнал решений.
> Идея — дать нашей же методологии Material Passport / Decision Lineage применяться к правилам,
> из которых она состоит (dogfooding).

## Зачем это нужно

Правила ai-rules разложены по слоям (`AGENTS.md` → `claude/CLAUDE.md` / `codex/AGENTS.md` →
`memory-bank/` → `skills/` → `templates/`) и синкаются в машинные локации (`~/.codex/AGENTS.md`,
`~/.claude/skills/`) через `sync-rules.bat`. Между слоями и снимками возникает **drift**:
устаревшие ссылки, рассинхрон снимка Codex, разросшиеся файлы, случайные секреты.

Раньше drift ловился вручную (см. git-историю: несколько коммитов `fix drift` подряд).
Теперь — детерминированным линтером.

## Инструменты

### `scripts/rules-lint.mjs`

Node-скрипт без зависимостей (boring tech; node, не python — python3 в среде сломан).
Запуск: `node scripts/rules-lint.mjs`. Exit 1 при ошибках, 0 при чистоте. Гоняется
автоматически в конце `sync-rules.bat`.

| Правило | Что проверяет | Уровень |
|---|---|---|
| **R1 stale-ref** | ссылки на `.md` разрешаются в реальный файл (учитывает непоследовательный стиль путей: `craft/<name>.md`, `<name>.md`, `memory-bank/<name>.md`). Артефакты пайплайна и внешние пути (`~/`, `RULES_ROOT`) — в allowlist | error (path со `/`) / warn (bare) |
| **R2 stale-command** | команды, ссылающиеся на `scripts/*` и файлы репо, существуют | warn |
| **R3 max-lines / token-budget** | bloat = файл длинный (>220 строк) **И** тяжёлый (>6000 токенов) одновременно; отдельно — короткий-но-тяжёлый файл (>6000 токенов) | warn |
| **R4 secret** | hardcoded API-ключи/токены в тексте правил | error |
| **R5 skill-shape** | `skills/*` в kebab-case, есть `SKILL.md` с `name`/`description` | error |
| **R6 sync-drift** | `~/.codex/AGENTS.md` покрывает источник (`AGENTS.md` + `codex/AGENTS.md`) построчно; `RULES_ROOT`-подстановка игнорируется | error |

### Источники модели правил

Заимствовано из экосистемы (`awesome-claude-code`), переработано под нашу структуру:

- **Ctxlint** — `stale-file-ref`, `stale-command`, `max-lines`, `token-budget`, `mcp-hardcoded-secret` → наши R1–R4.
- **agnix** — валидация skill-naming (`code-review`, не `Review-Code`) и shape SKILL.md → наш R5.
- **compass** — паттерн «единый источник + CI-валидация против drift» → R6 + встраивание линтера в `sync-rules.bat`.
- **Claude Code Safety Guard** — модель детерминированного PreToolUse-блока опасных команд → план Фазы 2 (см. Lineage #L2).

## Что НЕ взято (осознанно)

- **agnix целиком** (432 правила) — избыточно для нашей системы; взяли только принцип skill-shape.
- **cost-tiered routing** (compass) — у нас роли делятся Claude/Codex, не по цене модели.
- **Memory / Observability** проекты — вне текущего scope.

## Decision Lineage (append-only)

### #L1 — Линтер правил + CI-валидация синка (2026-07-13)
**Решение:** добавлен `scripts/rules-lint.mjs` (R1–R6) и вызов из `sync-rules.bat`.
**Почему:** правила дрейфили между слоями, ловилось вручную. Модель — Ctxlint/agnix/compass.
**Проверено:** первый прогон дал 122 «ошибки» — оказались ложными (ссылки на выходные артефакты
пайплайна `artifacts/*.md`, которых нет в репо правил by design). После allowlist пайплайн-артефактов
и внешних путей: **0 ошибок, 2 warn** (bloat в `pd-workflows/component-documentation.md` 296 строк
и `skills/craft-audit/SKILL.md` 254 строки).
**Наблюдение:** гипотеза о рассинхроне снимка Codex НЕ подтвердилась — построчная проверка показала
0 смысловых расхождений (2 «отсутствующие» строки = намеренная подстановка `RULES_ROOT`). Первая
версия R6 (substring) давала false positive; заменено на построчное покрытие.

### #L2 — Enforcement-хук guard-hook (ПОДКЛЮЧЁН локально, 2026-07-13)
**Решение:** `scripts/guard-hook.mjs` — детерминированный PreToolUse-блок всегда-запрещённых команд
(`rm -rf /`, `rm -rf ~`, `git reset --hard`, force-push без lease, `commit --no-verify`, `commit --amend`,
`mkfs`, `dd of=/dev/*`, fork-бомба, рекурсивный chmod/chown на системных путях, обход GPG). Модель Safety Guard.
**Wiring:** по решению пользователя вынесен ГЛОБАЛЬНО в `~/.claude/settings.json` (PreToolUse, matcher Bash) —
покрывает все проекты на машине. Локальный дубль из `.claude/settings.local.json` убран (иначе двойной прогон).
Обе settings-локации gitignored/per-machine — в репо уезжает только сам скрипт `scripts/guard-hook.mjs`.
**Проверено:** 6/6 опасных команд блокируются, 7/7 рабочих (`rm -rf ./build`, `--force-with-lease`,
`git commit -m`, `reset --soft`, `corepack pnpm`) проходят — ложных срабатываний нет.
**Важно:** хук активируется при **перезапуске сессии** Claude Code (хуки читаются на старте).
В текущей сессии ещё не действует.
**Открытые вопросы:** (1) выносить ли на глобальный уровень после обкатки; (2) держать конфиг хука
в ai-rules и синкать через sync-rules.bat, или вести per-project; (3) Codex/сабагенты — non-inheritance
разрешений пока не реализован (нужен отдельный agent-scoping механизм).

### #L3 — Уточнение R3 (2026-07-13)
**Решение:** `max-lines` теперь срабатывает только вместе с превышением токен-бюджета (длинный И тяжёлый).
**Почему:** первые два срабатывания (`component-documentation.md` 295 строк / ~2153 токена,
`craft-audit/SKILL.md` 253 / ~3341) при разборе оказались обоснованно длинными (шаблон-с-примерами и
плотный skill), но под токен-бюджетом. Порог по строкам был строже токеновой реальности → ложный шум.
**Результат:** линтер полностью чист (0/0). Настоящий bloat (длинный + тяжёлый) по-прежнему ловится.

### #L4 — Codex-first + замкнутый цикл обучения (2026-10-18)
**Решение:** роли перевёрнуты — Codex стал основным рантаймом (пайплайн + код), Claude сведён
к специалисту по Figma. Добавлен цикл обучения: наблюдения → инстинкты → инжект → промоушен в правила.
**Почему:** (1) пользователь работает преимущественно в Codex, а скиллы ему не раздавались вообще —
`sync-rules.bat` копировал только в `%CLAUDE_HOME%`, то есть весь слой скиллов был де-факто Claude-only;
(2) система была статичной: правила менялись только вручную, урок каждой сессии терялся — видно по
серии коммитов `fix drift` в истории.
**Модель:** ECC `continuous-learning-v2` (инстинкты, confidence 0.3–0.9, scope project/global).
**Отличие от источника:** у ECC инстинкты навсегда остаются в data-каталоге. Здесь добавлен последний
шаг — промоушен созревшего инстинкта в `memory-bank/` через ревью пользователя, после чего правило
раздаётся обоим рантаймам. Это и делает репозиторий самообучающимся.
**Реализация:** Node, без фонового демона. Прямой порт ECC невозможен: их observer не выживает на
нативной Windows (их же документация, issue #2489), а `python3` на этой машине — WindowsApps-stub,
который печатает `Python` и выходит, из-за чего их `observe.sh` молча ничего не делает.
**Проверено:** цикл прогнан end-to-end — захват промпта и вызова инструмента → создание инстинкта →
рост уверенности до 0.80 → инжект в SessionStart → опровержение (0.50) → отсечка по порогу 0.7.
`install-hooks.mjs` идемпотентен (повторный запуск не плодит дублей), `mcpServers` в settings.json
сохраняются. Контракт вывода SessionStart (`hookSpecificOutput.additionalContext`) оказался общим
у Codex и Claude Code — один скрипт обслуживает оба рантайма.
**Открытые вопросы:** (1) Ф3 (принуждающие хуки: anti-slop, routing-hint, delivery-gate) отложена
по решению пользователя; (2) пересечение четырёх craft-источников (`craft-audit`,
`make-interfaces-feel-better`, `motion-rules`, `emil-design-eng`) не разрешено; (3) скиллы Эмиля
живут в `~/.codex/skills/` вне репозитория, без версионирования.

### #L5 — Исправления, найденные при включении (2026-10-18)
**guard-hook, ложное срабатывание:** правило «`rm -rf /`» блокировало удаление **любой** папки по
абсолютному пути, потому что в Git Bash на Windows абсолютный путь начинается с `/` (`/c/Users/...`).
Поймано на живой команде при первом же применении хука. Теперь цель обязана заканчиваться сразу после
корня или быть глобом (`/`, `/*`, `/c/`, `~`). Регрессия: 27 кейсов (15 блок / 12 пропуск) — все верны.
**guard-hook, рантайм-агностичность:** проверка `tool_name !== "Bash"` отключила бы хук в Codex молча,
т.к. там инструмент шелла называется иначе. Теперь проверяется наличие строки команды, а не имя инструмента.
**rules-lint R1:** относительные ссылки вида `../<sibling>/SKILL.md` не резолвились (не передавался
файл-источник) и падали в неоднозначность по basename. Линтер стал полностью чист: 0 ошибок, 0 предупреждений.

### #L6 — Скиллы Эмиля в source of truth + разведение craft-пересечения (2026-10-18)
**Решение:** все 15 скиллов `emilkowalski/skills` (коммит `2d22863`, MIT) завендорены в `skills/`
и раздаются обоим рантаймам. Закрывает открытые вопросы (2) и (3) из #L4.
**Почему все 15, а не подмножество:** решение пользователя.
**Целостность:** `SKILL.md` вендоренных не редактируются — правка потерялась бы при обновлении
из апстрима, а расхождение было бы незаметным. Проверено побайтово: 0 расхождений с апстримом.
Провенанс, лицензия и процедура обновления — `skills/VENDOR.md`. `agents/openai.yaml` у них —
наш файл (в апстриме его нет); флаг `disable-model-invocation` апстрима отражён как
`allow_implicit_invocation: false` у `pick-ui-library`, `prototype`, `review-animations`.
**Разведение:** граница проведена по **масштабу и типу вопроса**, а не по теме:
экран целиком → `craft-audit`; одна деталь → `make-interfaces-feel-better`; «как надо?» →
`emil-design-eng`; конкретная работа с движением → профильный скилл Эмиля. Сужено описание
`craft-audit` — он претендовал на правила анимации (Comeau/Kowalski), которые теперь лучше покрыты
первоисточником. Описания Эмиля не тронуты — они уже взаимно разведены автором.
Авторитетная таблица — `skills/README.md`, краткая — `rules-index.md`.
**Приоритет при конфликте:** наши `memory-bank/craft/motion-rules.md` и токены DS проекта выше
скиллов Эмиля (`AGENTS.md` → «Приоритет источников»: memory-bank 4 > внешние практики 7).
**rules-lint:** R1/R2/R3 не применяются к вендоренным (их ссылки — на `plans/` целевого проекта,
объём задан автором). R4 (секреты) и R5 (форма) — применяются; проверено подложенным ключом.
Список берётся из блока ` ```vendored ` в `skills/VENDOR.md` — один источник.
**Цена:** список скиллов вырос с 15 до 30 в обоих рантаймах — больше контекста на листинг и больше
кандидатов на матч. Смягчено явными «НЕ для X» и тремя скиллами только по явному вызову.

### #L7 — Override #L6: первоисточники выше memory-bank в движении и деталях (2026-10-18)
**Отменяет:** приоритет из #L6 («наши `motion-rules.md` и токены DS выше скиллов Эмиля»).
**Решение:** как делать движение и детали интерфейса — решают завендоренные скиллы
(Эмиль, `make-interfaces-feel-better`, `apple-design`). Выше них — только токены конкретного
проекта. Исключение записано в `AGENTS.md` → «Приоритет источников».
**Почему (не уступка, а сверка):** пользователь сказал, что доверяет первоисточникам больше.
Проверено построчно — на каждом расхождении ошибался наш пересказ, а не оригинал:
1. `ease-in` на уход элемента — Эмиль: «Never use ease-in for UI animations»;
2. reduced motion → `transition: none` (к тому же невалидный CSS) — Эмиль, `apple-design`, MIFB:
   «fewer and gentler, not zero»;
3. hover 125/450ms как образец в 7 местах, приписан Эмилю — MIFB: частое ≤150ms; у Эмиля
   асимметрия про удержание/отпускание, не про hover.
Плюс 6 случаев, где мы строже первоисточника: «только transform/opacity» (хотя Эмиль строит на
`clip-path` и blur), «≤300ms для всего» (модалки/drawer 200–500ms), `will-change` заранее,
iOS через длительности вместо пружин, CSS > JS без оговорки о жестах, hover-scale без
`@media (hover: hover)`. И пробелы: модалка не растёт из триггера; обводка картинок требует чистый чёрный.
**Первопричина:** `motion-rules.md` был пересказом, сделанным при исследовании, и эти правила
были пересказаны ещё в 6 файлах. Пересказ дрейфует; пока оригинала в репо не было — незаметно.
Нарушался собственный принцип «одно правило — одно место».
**Исправление:** `motion-rules.md` переписан в маршрутизатор + шпаргалку, где у каждой строки указан
источник и действует правило «расходится со скиллом — прав скилл». Пересказы убраны из `craft-core`,
`anti-slop-audit`, `craft-audit`, `frontend-impl`, `frontend-implementation-rules`, `mobile-craft-rules`,
`tokens-spec` (там же: easing-токен `accelerate` = ease-in убран из таксономии; рассинхрон
`medium`/`standard` в именах длительностей).
**Между первоисточниками:** движение — Эмиль, поверхности/типографика — MIFB, жесты — `apple-design`.
**Стек:** shadcn/ui по умолчанию; `pick-ui-library` — по явному запросу для задач вне стека;
его base-ui для unstyled-компонентов в проектах на shadcn не применяется.
